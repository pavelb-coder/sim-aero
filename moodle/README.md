# АэроЛаб для Moodle — `mod_aerolab`

Плагин активности **«АэроЛаб: аэробенч»**: интерактивные авиационные симуляторы
(Аэродинамическая труба, Вентури, Винт, Конструктор БПЛА, PID-бенч, Pixhawk, Сборка квадрокоптера, Квиз) прямо внутри курса Moodle.

Ученик работает с тренажёром во встроенном окне, выполнение фиксируется автоматически (сигнал из АэроЛаб) и уходит в журнал оценок. Учитель видит отчёт и выгружает CSV.

- Целевая версия: **Moodle 4.5 LTS** (`requires = 2024100700`)
- Код плагина лежит в этой папке: `moodle/mod/aerolab/` — копия того, что должно оказаться в `<moodle>/mod/aerolab/`
- Ветка: **moodle-plugin** в репозитории `pavelb-coder/sim-aero` (ветка `main` — сам АэроЛаб)

---

## Установка

### Вариант А — копированием файлов

```bash
git clone -b moodle-plugin https://github.com/pavelb-coder/sim-aero.git
cp -r sim-aero/moodle/mod/aerolab <moodle-root>/mod/
```

Затем откройте **Администрирование → Уведомления** (админка сама предложит обновить базу), после чего очистите кэши: **Администрирование → Разработка → Очистить все кэши**.

### Вариант Б — в git-репозитории Moodle

```bash
cd <moodle-root>
git remote add aerolab https://github.com/pavelb-coder/sim-aero.git
git fetch aerolab moodle-plugin
git subtree add --prefix=mod/aerolab aerolab moodle-plugin --squash   # или cherry-pick папки moodle/mod/aerolab
```

(Для subtree-подхода достаточно папки `moodle/mod/aerolab` из ветки `moodle-plugin`.)

## Использование в курсе

1. В режиме редактирования добавьте активность **«АэроЛаб: аэробенч»**.
2. Заполните:
   - **Название** и **описание** (что ученик должен сделать);
   - **Адрес АэроЛаб** — по умолчанию публичный стенд `https://pavelb-coder.github.io/sim-aero/`; для закрытой установки укажите своё зеркало (любой статический хостинг папки сайта);
   - **Высота окна** — 640…900 пикселей;
   - **Что нужно выполнить для зачёта** — отмечайте достижения АэроЛаб (можно несколько: например, «Сборщик БПЛА» + «Допуск к полётам»);
   - **Оценка** — максимальный балл (по умолчанию 100);
   - **Завершение элемента** — рекомендуем «Требовать получения оценки» (completion → *receive grade*): тогда галочка выполнения встаёт автоматически при зачёте.
3. Сохраните. Ученик открывает активность → работает с АэроЛаб во встроенном окне → при получении нужных достижений они фиксируются, оценка проставляется автоматически.

### Как именно фиксируется выполнение

- АэроЛаб (начиная с коммита `fabc655`) отправляет родительскому окну события `postMessage`:
  `{source:'aerolab', type:'ready', achievements:[...]}` при загрузке и
  `{source:'aerolab', type:'achievement', id:'wiring_ok'}` при получении каждого достижения.
- Страница активности слушает эти события и записывает их в таблицу `aerolab_progress`
  (тип записи `auto`, видно учителю в отчёте).
- При загрузке страницы автоматически «подтягиваются» достижения, уже полученные учеником в браузере (сигнал `ready`).
- Если сигнал не дошёл (устаревшее кэшированное АэроЛаб, строгий CSP, приватный режим) —
  ученик может нажать **«Отметить выполненным вручную»** (запись `manual`, тоже видно в отчёте).
- Оценка никогда не снижается автоматически: проставляется максимум при выполнении всех требуемых пунктов.

### Отчёт

`/mod/aerolab/report.php?id=<cmid>` доступен учителям (право `mod/aerolab:manage`):
таблица «ученик × требуемое достижение» с источником (`auto`/`manual`) и временем + **выгрузка CSV** (Excel-совместимая, с BOM).

## Что внутри

```
mod/aerolab/
  version.php            — метаданные плагина (Moodle 4.5, ветка 405)
  lib.php                — точки входа Moodle: instances, grades, capabilities, утилиты
  mod_form.php           — форма активности (название, описание, URL, высота, чек-боксы достижений, оценка)
  view.php               — страница ученика: чек-лист прогресса + iframe + postMessage-мост
  ajax.php               — JSON endpoint для записи достижений (sesskey + capability)
  report.php             — отчёт учителя + CSV
  index.php              — список активностей АэроЛаб в курсе
  settings.php           — админ-настройки (URL и высота по умолчанию)
  styles.css             — стили страницы
  pix/icon.svg           — иконка активности
  db/install.xml         — таблицы aerolab, aerolab_progress
  db/access.php          — mod/aerolab: addinstance / view / manage
  db/upgrade.php         — заготовка миграций
  classes/privacy/provider.php — GDPR (экспорт/удаление данных)
  backup/moodle2/        — бэкап/восстановление активности (прогресс учеников не переносится)
  lang/ru, lang/en       — строки
```


## Синхронизация веток

Ветка `moodle-plugin` = `main` + папка `moodle/`. При каждом обновлении `main` ветку
moodle-plugin также обновляют слиянием (не rebase — история уже опубликована):

```bash
git checkout moodle-plugin && git merge main --no-edit && git push
```

Конфликтов не ожидается: ветки трогают разные файлы (в `main` папки `moodle/` нет).
После слияния проверьте, что приложение по-прежнему открывается, и оставьте ветку
moodle-plugin на origin в актуальном состоянии.

## Безопасность и приватность

- Запись прогресса — только для залогиненного владельца активности c правом `mod/aerolab:view` и валидным `sesskey`.
- `postMessage` принимается только с origin, заданного в настройках активности (сверка `e.origin`).
- Хранятся только: id достижения, время и способ фиксации. GDPR-провайдер реализован (экспорт/удаление).
- Бэкап курса переносит настройки активности, но **не** учебные данные учеников.

## Ограничения и проверка

- Код не прогонялся на живом Moodle в этой среде. Перед боевым применением проверьте на стенде:
  установка → добавление активности → ученик получает достижение в АэроЛаб → галочка в чек-листе → оценка в журнале → отчёт → CSV → бэкап/восстановление.
- postMessage-мост требует АэроЛаб не старше `fabc655` (ветка `main`).
- При «ручной» отметке плагин доверяет ученику — это видно в отчёте (`manual`), учитель может перепроверить и снять балл вручную.
